# а3 — сайт цифрового агентства

Статика (HTML/CSS/JS), 23 страницы: главная, хаб услуг, 12 страниц услуг,
О нас, Контакты, Кейсы, Блог (+3 статьи), Стать партнёром, Политика.
SEO-разметка (meta, Open Graph, Schema.org), sitemap.xml, robots.txt.
Формы на Formspree.

## Публиковать можно только собранное

Исходники — шаблоны. Домен и контакты в них не зашиты, вместо них
`{{SITE_ORIGIN}}`, `{{CONTACT_EMAIL}}` и условные блоки. Причина: в первой
версии домен стоял в 25 файлах и ~160 местах, и там полгода жил `ortus.ru` —
домен **чужой компании**. Вся SEO-разметка и все репосты работали на чужой
бренд, потому что поправить его нужно было в двадцати пяти местах.

```
npm run check     # проверить конфиг, ничего не собирая
npm run build     # исходники + site.config.json → dist/
npm test          # 19 тестов: не врёт ли витрина
```

`npm run build` **падает**, если домен не задан или если в него вписали
`ortus.ru`. Раздавать хостингу нужно `dist/`, а не корень репозитория.

## Один шаг при покупке домена

Купить домен → вписать одну строку и собрать:

```
SITE_ORIGIN=https://ortusdigital.ru npm run build
```

или один раз прописать в `site.config.json` → `"origin"`. Больше домен
нигде не встречается.

## Что настраивается тем же конфигом

| Поле | Переменная окружения | Если пусто |
|---|---|---|
| `origin` | `SITE_ORIGIN` | **сборка падает** |
| `email` | `SITE_EMAIL` | блока «Email» и ссылки в футере нет, `contactPoint` из JSON-LD убран |
| `telegram` | `SITE_TELEGRAM` | карточки Telegram нет |
| `whatsapp` | `SITE_WHATSAPP` | карточки WhatsApp нет |
| `phone` | `SITE_PHONE` | телефона нет |
| `legal` | `SITE_LEGAL` | строки реквизитов нет |
| `metrikaId` | `SITE_METRIKA_ID` | счётчик не грузится и не делает запросов |

Правило одно: **незаданный канал не рисуется вовсе**. Мёртвая кнопка хуже
отсутствующей. Когда не задан ни один прямой контакт, страница контактов
честно говорит, что единственный рабочий способ связи — форма.

## Выбор варианта дизайна

Вариант ещё не выбран, поэтому на стенде работает переключатель в правом
нижнем углу. Три варианта на одних и тех же страницах:

| Вариант | Что это |
|---|---|
| **Aurora** | базовый: ирис `#5A5FE0` → мята `#37B6A6`, светлый фон, пятна за героем, градиенты |
| **Системный** | личная дизайн-система: синий `#225AEA`, плоско, без градиентов и свечений |
| **Тёмный** | палитра макета `дизайн-версии/ortus-dark`: чёрный `#0C0C0C`, Montserrat, пурпур `#B600A8`, металлический градиент в заголовке |
| **DesignPro** | палитра макетов `designpro-hero` и `ortus-designpro`: чёрный, Inter, голубой `#64CEFB` |

```
SITE_ORIGIN=https://demo.invalid SITE_SKINS=1 npm run build
```

Без `SITE_SKINS=1` переключатель в сборку не попадает — на витрине для клиентов
его быть не должно, и это проверяется тестом. Выбор запоминается в браузере;
отдельный вариант открывается ссылкой, например `?skin=system`.

Варианты живут в `skins.css` как наборы токенов поверх базового слоя страниц.
Палитры трёх последних сняты с React-макетов в `дизайн-версии/`. `designpro-hero`
и `ortus-designpro` по цветам совпадают — второй форк первого под а3, различие
в контенте и видео-герое, которых в скине нет, поэтому вариант один. Сами
макеты остаются самостоятельными сборками: приёмы вроде magnetic hero, marquee
и видео на первом экране скином не передаются, их смотреть в самих проектах
(`npm run dev` в папке макета).

## Деплой

Любой статический хостинг раздаёт `dist/` как есть (`index.html` — главная).
Cloudflare Pages / Netlify / GitHub Pages / Vercel: команда сборки
`npm run build`, каталог публикации `dist`, домен задать переменной
окружения `SITE_ORIGIN` в настройках проекта.
